Introduction

Memory Infrastructure for Engineering Teams

Supadense gives every developer and engineering team a persistent, local-first brain that lives inside the codebase — capturing decisions, docs, and context so Claude Code always knows what matters.

Local-First by Design

Your brain files live in .supadense/ inside your project. Nothing leaves your machine unless you push it. No vendor lock-in. Works offline. Commits alongside code.

What Is Supadense?

When you work on a codebase with Claude Code, context disappears between sessions. Architecture decisions, why you chose one library over another, that tricky edge case you solved last week — all gone. Supadense solves this by maintaining a structured knowledge layer per project that Claude automatically reads and writes.

It's three things in one:

🧠

Persistent Brain

L0 / L1 / L2 layered memory that grows as you work. Decisions, patterns, and summaries — auto-synthesised by Claude.

📄

Source Library

Capture URLs, PDFs, notes, and docs into .supadense/sources/. Airtop extracts clean markdown from any page.

🔗

MCP Server

Claude Code reads and writes memory via a local MCP server wired up automatically through .mcp.json.

Who Is It For?

👩‍💻

Solo Developers

Never lose context between Claude sessions. Your decisions persist.

👥

Engineering Teams

Shared .supadense/brain/ committed to git. New joiners onboard instantly.

🏗️

Monorepos

One brain per service, or a shared root brain — your choice.

Quickstart

Up and Running in 2 Minutes

Install the CLI, log in, and initialise your first project.

1. Install

Supadense requires Bun (≥ 1.0) and Claude Code.

bash
# Install Bun if you don't have it
curl -fsSL https://bun.sh/install | bash

# Install Supadense CLI
curl -fsSL https://supadense.ai/install.sh | bash

2. Log In

bash
supadense login

This stores your API token at ~/.supadense/config.json. The token is only used to sync brain files to your Supadense account if you choose to push.

3. Initialise a Project

bash
cd ~/projects/my-api
supadense init

This creates .supadense/ inside your project and writes .mcp.json so Claude Code automatically connects.

What gets created

.supadense/brain/L0/ — raw decisions & facts
.supadense/brain/L1/ — synthesised summaries
.supadense/brain/L2/ — durable patterns
.supadense/sources/  — captured docs & URLs
.mcp.json — MCP server config for Claude Code

4. Start Claude Code

bash
claude

Claude Code picks up .mcp.json automatically. The supadense-brain MCP tool is now available in every session. Claude will read relevant context before answering and write decisions back to memory.

5. Capture Your First Source

bash
supadense sources add https://docs.example.com/api-reference

The URL is scraped via Airtop (full JS rendering) and saved as clean markdown in .supadense/sources/. It appears in the Supadense dashboard and in your graph within seconds.

Concepts

How Supadense Works

Supadense turns your codebase into a living knowledge base. Here's the full picture.

The .supadense/ Folder

Everything Supadense stores lives inside your project at .supadense/. This is intentional — your knowledge commits with your code, diffs with PRs, and travels with clones.

tree
my-project/
├── src/
├── .supadense/
│   ├── brain/
│   │   ├── L0/          # decisions, raw facts, notes
│   │   ├── L1/          # synthesised summaries
│   │   └── L2/          # durable patterns & architecture
│   └── sources/         # captured URLs, PDFs, docs
├── .mcp.json            # auto-connects Claude Code
└── .gitignore           # brain/ excluded by default

Brain Layers Explained

⚡

L0 — Raw Capture

Decisions as they happen. "Chose Postgres over MySQL because of JSONB support." Verbatim, timestamped, unfiltered.

🔄

L1 — Summaries

Claude periodically synthesises L0 into concise summaries. Older entries collapse into patterns. Saves context window.

🏛️

L2 — Architecture

Durable, high-signal patterns. Rarely changes. This is your project's architectural DNA — conventions, constraints, non-negotiables.

The MCP Loop

Every Claude Code session runs the supadense-brain MCP server as a sidecar process. Claude uses it automatically:

1

Session Start — Read

Claude queries the MCP server for relevant context based on the current task. L2 patterns always load; L1 and L0 are retrieved by semantic similarity.

2

During Work — Write

When Claude makes a decision or learns something new, it writes to L0/ via the MCP write_brain tool. Atomic, append-only.

3

Synthesis — Compress

Periodically (or on demand), Claude synthesises L0 → L1 → L2. Older facts compress into higher-layer abstractions.

Source Processing Pipeline

When you add a URL via supadense sources add or the Capture button:

Queued
→
Airtop fetch
→
Markdown extract
→
Saved to sources/
→
Brain indexed
→
Done
Why Airtop?

Plain HTTP fetch fails on SPAs, paywalled content, and login-required pages. Airtop runs a full browser — it handles React apps, Twitter threads, documentation sites, and more.

Core Concepts

Brain Layers

The brain is a three-layer knowledge pyramid. Each layer has a distinct purpose and lifetime.

Layer Structure

LayerPurposeWritten byLifetime
L0/Raw decisions, facts, notesClaude (MCP) or CLISession-level
L1/Synthesised summariesClaude (on demand)Sprint-level
L2/Durable architecture patternsClaude + human reviewProject lifetime

File Format

All brain files are plain .md with a simple frontmatter convention:

markdown
---
slug: L0/auth/jwt-decision
created: 2025-06-09T14:32:00Z
session: abc123
---

# Chose JWT over sessions

Stateless auth needed for horizontal scaling. Refresh token stored
in httpOnly cookie. Access token 15min TTL.

## Trade-offs accepted
- Cannot revoke individual tokens instantly
- Client must handle refresh logic

Writing to Brain from Claude

Claude uses the MCP write_brain tool automatically. You can also write manually:

bash
supadense brain write --layer L0 --title "Switched to Drizzle ORM" "Replaced Prisma — Drizzle has better TS inference and no binary dependency."

Committing Brain Files

Default: Brain is gitignored

On supadense init, .supadense/brain/ is added to .gitignore. This keeps personal context private.

To share brain with your team, remove the gitignore line. Brain files then ship with your repo — new team members get full project history on git clone.

Core Concepts

Sources

Sources are external documents — URLs, PDFs, notes — captured into .supadense/sources/ as clean markdown. Claude can read them as project context.

Adding Sources

bash
# Add a URL (scraped via Airtop)
supadense sources add https://docs.stripe.com/api

# Add to a specific project
supadense sources add https://arxiv.org/abs/2310.01344 --project my-ml-project

# Add to all projects
supadense sources add https://example.com/shared-style-guide --all-projects

Supported Content Types

TypeHow to addNotes
URL / Web pagesources add <url>Full JS rendering via Airtop
GitHub reposources add https://github.com/…README + key files extracted
arXiv papersources add https://arxiv.org/…Abstract + full text
Plain text / noteCapture dialog → Paste textSaved immediately
Twitter/X threadsources add https://x.com/…Requires Airtop API key

Managing Sources

bash
# List sources in current project
supadense sources list

# Interactive remove (numbered picker + confirm)
supadense sources remove

# Delete from ALL projects everywhere
supadense sources delete

Sources in the Dashboard

Every captured source appears in the Sources tab of the Supadense web UI with its real title (extracted from the # heading), status badge, and project pills. Sources are automatically synced to the local .supadense/sources/ folder — fully bidirectional.

Core Concepts

MCP Server

Supadense exposes a Model Context Protocol server that Claude Code connects to automatically via .mcp.json.

Auto-Configuration

supadense init writes this into your project root:

json — .mcp.json
{
  "mcpServers": {
    "supadense-brain": {
      "command": "bun",
      "args": ["run", "~/.supadense/stdio.ts"],
      "env": {
        "SUPADENSE_URL":     "http://localhost:4096",
        "SUPADENSE_TOKEN":   "<your-token>",
        "SUPADENSE_PROJECT": "my-api"
      }
    }
  }
}

Available MCP Tools

ToolDescription
read_brainRetrieve relevant memory chunks by semantic query
write_brainAppend a new fact or decision to L0
list_sourcesList all captured sources for the current project
read_sourceRead the full content of a specific source file
search_brainFull-text search across all brain layers

Using from Claude

claude code prompt
# Claude reads memory automatically
What database are we using and why?
# → Claude calls read_brain("database choice") and answers from L0/L1

# Claude writes decisions automatically
We're switching to Drizzle ORM instead of Prisma.
# → Claude calls write_brain() to record this in L0

CLI Reference

init / deinit

supadense init

Register the current directory as a Supadense project.

bash
supadense init [--name <name>]
FlagDefaultDescription
--namedirectory nameDisplay name for the project

Creates: .supadense/brain/{L0,L1,L2}/, .supadense/sources/, .mcp.json, updates .gitignore.

supadense deinit

Unregister a project and remove all local Supadense files.

bash
supadense deinit [-f] [project-id]
supadense deinit --disk-only [-f]
FlagDescription
-f / --forceSkip confirmation prompt
--disk-onlyOnly delete .supadense/ from disk (project already unregistered)

Also removes supadense-brain from .mcp.json and cleans up .gitignore.

supadense projects

List all registered projects with their IDs and paths. The current project (based on cwd) is marked with ▶.

bash
supadense projects

supadense status

Show the status of the current project — brain file count, last sync, GitHub repo.

bash
supadense status

Teams & Monorepos

Sharing Brain with Your Team

By default brain files are gitignored (personal context). To share with your team, remove the gitignore line:

bash — .gitignore
# Remove this line to share brain with team:
# .supadense/brain/

# Sources are never committed (usually large)
.supadense/sources/
Team Workflow Tip

Commit L2 (architecture patterns) and L1 (summaries) to git. Keep L0 (raw session notes) gitignored per-developer. This gives the team durable context without noisy per-session writes.

Monorepo Setup

Each service or package can have its own .supadense/. You can also have a root-level brain that spans the whole repo:

tree
monorepo/
├── .supadense/          # root brain — shared architecture
├── packages/
│   ├── api/
│   │   └── .supadense/ # api-specific brain
│   └── web/
│       └── .supadense/ # frontend-specific brain
└── .mcp.json

Register each with supadense init from inside its directory. The MCP server handles multiple registered projects simultaneously.

GitHub Integration

Supadense can detect the GitHub repo associated with a project and surface live PR and issue activity in the dashboard.

Auto-Detection

On supadense init, Supadense reads .git/config and parses the remote origin URL (SSH or HTTPS). The repo is stored in the project record automatically.

bash
# Override or set manually
supadense github set owner/repo

Activity Dashboard

The project's right rail shows a live Activity card with:

  • Open PRs with review status (approved / changes requested / pending)
  • Draft PR badges
  • Open issues with labels
  • Comment counts and last-updated times
Rate Limits

Unauthenticated GitHub requests are limited to 60/hr. Connect your GitHub account in Settings → GitHub to get 5,000/hr. Activity is cached for 5 minutes.
